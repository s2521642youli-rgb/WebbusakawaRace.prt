# 顔パーツの追加方法

パーツ定義は **js/parts-config.js** に集約している。index.html・pasture.html・race.htmlを個別に編集する必要はない。ファイルを置くだけで自動発見する方式ではない。

## 今回の設定

| モデル | sizeMultiplier | fixedDepth | 深さの調整 |
|---|---:|---:|---|
| eye_01 / eye_02 | 0.48 | -0.10 | 可 |
| mouth_01 | 0.55 | -0.10 | 可 |
| mouth_02 | 1.10 | -0.13 | 固定（従来どおり） |
| mouth_03 | 0.715 | -0.16 | 固定（従来どおり） |
| mouth_04 | 0.55 × 固定追加倍率1.55 | -0.30 | 固定、前後傾きも−28°で固定 |
| mouth_05 | 0.55 × 固定追加倍率1.40 | -0.25 | 固定、前後傾きも0°で固定 |

sizeMultiplierは、GLBの最長寸法を頭の基準半径に対して何倍に合わせるかという値。新しい2つの口はmouth_01と同じ仮の基準値。目・口の取り付け処理、法線、回転方向、接地・歩行の仕組みは変更していない。

## 例：eye_06.glbを追加する

1. モデルを `assets/eyes/eye_06.glb` に置く。
2. `js/parts-config.js` の `partSettings` 内へ、次の1行を追加する。

```js
eye_06:{id:'eye_06',category:'eyes',label:'目の形06',path:'./assets/eyes/eye_06.glb',sizeMultiplier:.48,fixedDepth:-.1},
```

口なら `assets/mouths/`、categoryは `'mouth'` を指定する。パスは、jsフォルダからではなくHTMLのあるプロジェクトルートから指定する。既存のIDは保存データで使用しているので改名しない。

3. ローカルサーバーを動かし、**以前と同じURL・ブラウザ**でindex.htmlを再読み込みする。例：`http://127.0.0.1:8767/index.html`。目カテゴリ→「目①」または「目②」→新しいモデルを選ぶ。口も同様。
4. X・Y・回転・浮き具合を調整する。「なし」も選べる。リセットは選択モデルの初期深さと、その取り付け場所の初期位置へ戻す。
5. 登録して牧場で確認し、出走者に選んでレースでも確認する。

**保存データ**は従来の形式のまま：

```json
{"mouth_01":{"type":"mouth_04","x":0,"y":-0.35,"rotation":10,"depth":-0.07,"exists":true}}
```

この `mouth_01` は「口を付ける場所（スロット）」、`type`は「使うモデル」。目もスロットeye_01/eye_02を維持しながら、どちらにもeye_06などの形を選べる。口は1スロットなので複数モデルが同時に出ることはない。既存の保存済みデータを一括書換する処理は追加していない。depthがない旧データはモデルのfixedDepthへフォールバックする。

## ArUcoマーカー

モデル一覧とマーカー対応は別の定義になっている。現状の対応は変更していない。

| ID | スロット | 動かす形 |
|---|---|---|
| 0 | eye_01（目①） | 現在選択中の目の形 |
| 1 | eye_02（目②） | 現在選択中の目の形 |
| 2 | mouth_01（口） | 現在選択中の口の形 |

したがって、新しい口を**手動で選び、既存のID 2で動かすだけならマーカー追加は不要**。

新しいマーカーで形も指定したい場合、未使用IDを確認してから、同じファイルの `arucoMarkerBindings` へ追加する。以下は設定例であり、今回ID 3やID 6を実際に割り当ててはいない。

```js
export const arucoMarkerBindings={
  0:{slot:'eye_01'},
  1:{slot:'eye_02'},
  2:{slot:'mouth_01'},
  3:{slot:'mouth_01',model:'mouth_04'},
  6:{slot:'eye_01',model:'eye_06'}
};
```

同じスロット用の複数マーカーが同時に見えた場合は、小さいIDを優先する。口のID 2と3を同時に見せると2が優先されるので、形を切り替える際は使うマーカーだけを見せる。モデル切替中もWebSocket通信を維持し、取得したテンプレートを複製して使用する。

Python側の送信対象も `--ids` で合わせる：

```sh
python3 aruco_web_bridge.py --ids 0,1,2,3,6
```

### 約24個へ増やす際のPython側の注意

既存のaruco_web_bridge.pyと、そこから読み込む既存check.pyを確認した。今回Pythonは変更していない。

- bridgeは `check.parse_ids(args.ids)` を使用している。
- 実際のcheck.pyの `parse_ids` には **最大8種類** の上限がある。24個を指定するには、将来この上限またはbridge側のID検証を変更する必要がある。
- 既定のDICT_4X4_50はID 0〜49。24個の割当数自体は範囲内だが、同じ辞書を使ったマーカーを用意する必要がある。
- `measure_many` は一度のdetectMarkers結果を対象IDごとに処理しており、対象追加のたびに検出器を作り直す構造ではない。
- 多数のマーカーが同時に見える場合は実カメラで検出率・フレームレートを測る必要がある。今回24枚での実機検証は行っていない。

## 読み込みとキャッシュ

js/model-cache.jsでページごとにGLBテンプレートのPromiseをキャッシュする。同時リクエストも1回にまとめ、失敗した項目はキャッシュから外すので再試行できる。画面や個体へ置くときは既存どおりSkeletonUtils.cloneで骨を含めて複製する。牧場・レースでは保存データが実際に使う種類だけを読み込み、24種類すべてを毎回ロードする必要はない。

ブラウザでファイルを直接開かずローカルサーバーを使う。既存の `cloudflare/scripts/serve-project.py` はjs/とassets/も配信できる。CloudflareのWorkerは投票ページとAPI用であり、今回もPCの3D画面全体をWorkerへ公開する構成には変更していない。

読み込み失敗時は画面のメッセージとConsoleのファイル名・パスを確認する。GLBを追加しただけで定義を追加し忘れたり、大文字・小文字や連番を間違えないようにする。

## 大きさ・前後の傾きの調整

制作画面の各スロットに「大きさ」（0.25〜3.00倍、0.05刻み）と「前後の傾き」（−80〜80°、1°刻み）を追加した。
大きさはpartSettingsのsizeMultiplierを基準にした追加倍率。前後の傾きは頭の表面へ沿わせ、既存の平面回転を適用した後のローカルX軸で傾ける。プラスは上側が手前、マイナスは下側が手前。
モデル切替とArUco座標更新では調整値を保持する。リセットで倍率1・傾き0へ戻る。

保存する各パーツに `scale` と `tilt` を追加し、牧場とレースでも同じ姿勢を復元する。両方の値がない旧データは倍率1・傾き0なので見た目を維持する。既存のlocalStorageデータを一括書換する処理はない。

計算はjs/part-adjustment.jsにまとめた。サイズや傾きが変わった場合だけ外形・厚みと表面サンプリングを更新し、平面回転だけの変更では既存のRaycasterキャッシュを再利用する。

### mouth_04の固定値

2026-10-20の調整画像に合わせ、浮き具合−0.30・大きさ1.55倍・前後の傾き−28°を固定した。定義はjs/parts-config.jsのmouth_04。基本倍率0.55を変えず、追加倍率1.55を一度だけ適用するので、最終的なサイズ倍率は0.8525。X・Yと平面回転は引き続き調整できる。保存済みのmouth_04も復元時はこの固定値を優先するが、localStorage自体は書き換えない。

### mouth_05の固定値

画像に合わせ、浮き具合−0.25・大きさ1.40倍・前後の傾き0°を固定した。定義はjs/parts-config.jsのmouth_05。基本倍率0.55×追加倍率1.40＝0.77で、倍率の二重適用はしない。制作・牧場・レースで固定値を優先し、X・Yと平面回転は引き続き調整できる。既存の保存データ自体は書き換えない。

### モデル切替時の調整値（更新）

mouth_04・mouth_05の確定した見た目は読み込み設定として適用し、大きさ・浮き具合・前後傾きのバーは非表示にした。ほかのモデルではバーを引き続き使える。
別モデルへ切り替える際はX・Y・平面回転のみを保持し、大きさ・前後傾き・深さは切替先モデルの標準値に戻す。前のモデルの調整が次のモデルへ引き継がれることはない。同じモデルを押し直した場合は現在の調整を保持する。

### eye_03・eye_04の標準設定

画像に合わせ、両モデルは浮き具合−0.26・大きさ1.10倍・前後の傾き0°を読み込み時に適用する。基本倍率0.48×追加倍率1.10＝0.528。固定項目のバーは表示せず、X・Y・平面回転は引き続き調整可能。制作・牧場・レースで同じ設定を使用し、他モデルに調整値を引き継がない。保存データは一括書換しない。
