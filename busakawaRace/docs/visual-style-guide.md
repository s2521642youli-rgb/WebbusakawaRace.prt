# レース描画スタイルの比較試作

## 使い方
race.html の「管理設定」→「描画スタイル」で Original / Low Poly / Painterly Low Poly を選ぶ。初期値は Original。走行中も切り替えられる。管理設定を閉じれば観客向け画面に戻り、描画と通信は継続する。選択は保存データへ書き込まない。

## 実装
- race.html：選択UIとスタイル管理の呼び出しだけを追加。
- js/race-visual-style.js：材質、背景、ライトを独立して管理。
- Original：元の形状・材質・表示状態・背景・ライトを参照ごと復元。
- Low Poly：背景の粗い三角面、控えめな起伏、連続した淡い地表色、flatShading、少数の木・低木・岩。
- Painterly Low Poly：上記に淡い配色と128pxのプロシージャルな筆ムラを追加。走路は面別の塗り分けを廃止し、平面投影UVで不規則な濃淡を付ける。白いキャラクターには強い色やノイズを付けない。

キャラクターのジオメトリ、リグ、顔の位置・回転・スケールには触れない。OriginalとLow Polyのカメラ、走路座標、白線の材質と描画順を維持。Painterlyだけは低い近接カメラを使用。背景は走路から離して配置する。全面フィルター・外部アセット・新規ライブラリは使わない。

## 調整
js/race-visual-style.js 冒頭の raceVisualStyleConfig を編集して再読み込みする。

| 設定 | 内容 |
|---|---|
| seed | 背景の色ムラを再現する乱数シード |
| terrainSegments | 地面の分割数。小さいほど大きな面 |
| hillHeight | キャラクター全高を基準にした背景の起伏 |
| textureSize | 筆ムラテクスチャの解像度 |
| brushStrength | Painterlyの控えめな色ムラの強さ |
| lowPoly / painterly の sky, grass, track, leaf, rock, trunk | 各スタイルの配色 |
| faceVariation | 木・岩の面ごとの色差。草地・走路はこのランダム塗り分けを使わない |
| camera.startElevation / elevation | Painterlyのスタート・走行中のカメラの高さ成分 |
| camera.maxDistance | Painterlyの最大追従距離（全高の倍数）。大きく離れた集団は先頭側を優先 |
| camera.followPerSecond | Painterlyカメラの方位・距離・注視点の追従の速さ |
| hemi / key | 環境光・主光源の強さ |

新スタイルの専用背景は5描画バッチ（地面＋4種類のインスタンス群）。初回選択時に生成し、以降は再利用する。毎フレームのスタイル計算は行わず、破棄時は追加リソースだけを解放する。Originalのリソースは解放しない。

## 確認結果
- 実GLB4体で3種類を表示し、顔の突出・立体感とコースの視認性をブラウザで確認。
- 同一カメラ・同一姿勢の比較用環境で、変更前とOriginalのスクリーンショットがバイト単位で一致。
- 100回切り替え後も生成済みリソース数が増えず、Originalの材質・形状・ライトが完全復元されることを自動検証。
- 1〜4体、58通りの投票・ハプニング計画、途中のスタイル切替を自動検証。実到着順位・同着、顔の固定、走り抜け、再レースを確認。
- ブラウザ4体の実走で004が2票の1位、003が1票の2位、001・002が0票の3位同着を確認。Consoleエラーなし。
- オンライン連携の模擬通信テストでサーバー締切・票数確定・同着・0票停止・再試行・保存データ非変更を確認。

今回、実スマートフォンからの投票、本番Cloudflare通信、展示用PCでの長時間稼働・FPS計測は未確認。サーバー側のコードは変更していない。比較画像はテスト専用環境で顔見せの角度だけ0度に固定し、同じ構図で取得した（実装本体の顔見せ設定は変更していない）。

## 方向性の修正（2026-10-22）
原因は三角形単位のランダム色差と、扇状に分割された走路形状・既存UVへの適用。これが三角パターンと放射状の縞を作っていた。

地面は頂点の格子を不均一にし、連続ノイズによる起伏と穏やかな色の広がりで表現する。走路の頂点位置は変更せず、三角形単位の色差をゼロにしてXZ平面投影UVを使用。規則的な筆線は廃止し、低コントラストな不規則濃淡にした。木・低木・岩は立体形状を拡大し、個体サイズにばらつきを付けた。

Painterlyはカウントダウン中もキャラクター中心の低い構図を使用。走行開始と同時に追従し、コース全景を保持する時間を設けない。方位・距離を補間してカメラが集団を横切るのを避ける。走者が大きく離れた場合は全コースを収めず先頭側を優先する。Originalの構図と既存のゴール演出は変更しない。

修正版をブラウザでカウントダウン・走行・同着結果まで確認。テスト用の別オリジンだけに4体のデータを用意し、実際の登録データは編集していない。自動検証でPainterlyの1〜4体のレース全期間についてカメラ座標の有限性と先頭キャラクターの投影範囲も確認した。
